The Databricks ML Platform, End to End — with Genie Code

Attendees build a claim-case escalation model across every layer of the Databricks Data Science & ML platform, using Genie Code for ML as their AI pair-programmer — from EDA to a monitored, governed serving endpoint deployed as code.

01

What attendees walk away able to do

Build with Genie Code

Plan, write and run ML code from the Genie Code panel — EDA, features, XGBoost training, predictions — while reviewing every step.

Engineer governed features

Publish a Unity Catalog feature table and build training sets with lineage from feature to model.

Track, register & serve

Compare runs in MLflow, register the champion in Unity Catalog, score in batch and deploy a serverless endpoint.

Monitor & operationalise

Watch quality and drift with Data Quality Monitoring, and run the whole pipeline as scheduled jobs with champion/challenger promotion.

03

Assumptions & prerequisites

Workspace (confirm with Allianz)

  • Partner-powered AI features enabled for the account and workspace (required for Genie Code).
  • Catalog adp_workshop with USE CATALOG + CREATE SCHEMA for attendees.
  • Serverless notebooks and jobs (or DBR 16.4 LTS ML+ shared cluster).
  • Model Serving and Data Quality Monitoring available in the region.
  • Optional: curated adp.claims.cases table — otherwise the synthetic data is used.

At each seat

  • Git folder created from github.com/saswata30/Allianz_ML_Workshop.
  • 00_setup_data run once — personal schema ml_<user> with 60k labelled and 3k open cases.
  • Genie Code panel opens and Agent mode is available.
  • A small serverless SQL warehouse for the monitoring dashboard and alert.
